# scripts/bootstrap/

What runs before or outside the linked repo: the OS bootstrap (`macos/setup.sh`, `linux/setup.sh`; both take `-n` to report what they would install), `linux/harden.sh` with its check `linux/harden-test.sh`, and the setup scripts `install.sh` applies at the end: the optional installs and the roles' scripts ([`roles/README.md`](../../roles/README.md)). The installation rules in the [root `AGENTS.md`](../../AGENTS.md) apply here first of all: no reliance on the current PATH, closed stdin never hangs or opts into anything, and every run is safe to repeat. Which manager installs a package is in [`homebrew/README.md`](../../homebrew/README.md).

A new setup script is a file here named after its install or role. It skips what is already installed and is safe to run again.

## Linux

- `linux/setup.sh` installs `apt-packages.txt`.
- `linux/pihole.sh` sets up Pi-hole v6 with Unbound as its upstream, as the [Pi-hole guide](https://docs.pi-hole.net/guides/dns/unbound/) describes and `ph-test` checks. Unbound comes from apt, listens on `127.0.0.1#5335`, and must pass `unbound-checkconf` before Pi-hole is touched. Pi-hole comes from its official installer, unattended, pointed at Unbound with its own DNSSEC off; `PIHOLE_UPSTREAMS` overrides the upstreams. An installed Pi-hole is left to `pihole -up`, but every run brings its upstreams and DNSSEC setting back in line and warns when no web password is set (`sudo pihole setpassword` sets one). It needs root and re-runs itself through sudo. `PIHOLE_ROOT` prefixes every system path for the tests.
- `linux/harden.sh` locks down a Debian server or VPS: it upgrades packages, creates the admin user with passwordless sudo and the SSH keys, installs and connects Tailscale, writes `/etc/ssh/sshd_config.d/00-harden.conf` (keys only, no root login, only that user; checked with `sshd -t`), sets ufw to deny all inbound except `tailscale0`, Tailscale's UDP port, the `--allow` ports, and the `--lan` ports on the LAN only, and turns on unattended upgrades. It never runs unasked: `install.sh` offers it first, defaulting to no, on a Linux persona with `harden=yes` that `harden-test.sh --brief` finds unhardened; `--harden` and `--no-harden` answer without a terminal, closed stdin skips it, and `HARDEN_ARGS` adds its options. Run from the repo as the admin user, it re-runs itself through sudo, keeping `SSH_CONNECTION` and `TS_AUTHKEY`. Run as root on a box with no admin user yet, it creates one and needs nothing else from the repo: `ssh root@HOST 'bash -s -- --user NAME --allow 80 --allow 443' < scripts/bootstrap/linux/harden.sh`. `harden.sh --help` lists the options; `TS_AUTHKEY` joins the tailnet without a login URL. Everything that can stop it is checked before the first change: a key to give the admin user, a LAN when there are LAN ports, and Cloudflare's ranges for `--cloudflare`. On a Pi-hole (`/usr/bin/pihole-FTL` present) 53, 80, and 443 stay open to the LAN, plus DHCP and NTP when FTL serves them. Public SSH closes only when Tailscale is connected and this session came in over Tailscale or from the console; from anywhere else, or when the origin cannot be told, it stays open, rate limited, and the run says to log in over Tailscale and run again. Without a terminal it does not wait for a Tailscale login. Running it again rewrites only what differs; a port an earlier run opened stays open until `ufw delete` closes it. Docker-published ports bypass ufw.
- `linux/harden-test.sh` checks a box against what `harden.sh` leaves and changes nothing; it is the audit for any Linux box and needs nothing else from the repo: `ssh HOST 'sudo bash -s -- --user NAME' < scripts/bootstrap/linux/harden-test.sh`. It covers SSH, the admin user, Tailscale, the firewall (on a Pi-hole, 53 must be allowed from the LAN), Docker ports published to all interfaces, and updates. Without root it reads the config files the way sshd does and says which checks need sudo. It exits 0 when every check passes and 1 when any fails; `--brief` prints only the failures, which is how `install.sh` decides whether to offer `harden.sh`.

## macOS

- `macos/setup.sh` installs the Xcode Command Line Tools when missing and waits for the installer window by polling `xcode-select -p` (`CLT_WAIT_SECONDS` caps the wait), never for a keypress; then the Xcode license, Rosetta 2 on Apple Silicon, and `iterm2.sh`.
- `macos/holeberry.sh` installs Holeberry, a Pi-hole menu bar app with no cask. Off by default.
- `macos/iterm2.sh` applies the iTerm2 settings outside profiles: it enables the Python API, makes the repo's `dotfiles` profile the default by its `Guid`, and adds each repo `.itermcolors` file to iTerm2's Custom Color Presets. It writes only what is missing or differs and leaves other presets alone. Keep the `Guid` the same as in the profile ([`stow/README.md`](../../stow/README.md)).
