# homebrew/

Brewfiles and `brew.sh`. A persona's `brew` and `brew_optional` keys pick which Brewfiles install ([root `AGENTS.md`](../AGENTS.md)); `df-add brew NAME` adds a package for you ([`scripts/README.md`](../scripts/README.md)). `brew.sh` installs Homebrew if needed, runs `brew bundle install --no-upgrade` on each `brew` Brewfile (so a Brewfile is a plain bundle file, and an entry that only applies to macOS sits in an `if OS.mac?` block, as the casks in `Brewfile.core` do), offers the not-yet-installed entries of each `brew_optional` Brewfile in a picker on macOS (inside an install, `install.sh` asks that question up front: `brew.sh --pending` lists the entries and `DOTFILES_BREW_PICKS` carries the answer), trusts tap-qualified entries first (Homebrew 7 refuses untrusted taps), writes `$(brew --prefix)/etc/npmrc` with `cache=~/.cache/npm` (npm launched outside zsh, such as Claude's MCP servers through `npx`, never sees `NPM_CONFIG_CACHE` and would cache in `~/.npm`; a global npmrc without the repo's marker line is left alone with a warning), and ends with `brew cleanup`. `-n` reports what would be installed. A role's `brew` Brewfiles join the persona's. Upgrades are `os-doctor`'s job: it runs `brew upgrade --fetch-HEAD`, so a formula installed from HEAD (`args: ["HEAD"]`, as `xdg-ninja` is in `Brewfile.core` for its `$XN_IGNOREFILE` support) is rebuilt from new commits too, not only on a new release. The bundle's `--no-upgrade` leaves a stable copy installed earlier in place; run `brew reinstall --HEAD NAME` once on such a machine.

- Keep Brewfiles flat lists of entries: no comment explaining an entry and no `if OS.*` block beyond the one for casks. A package that doesn't suit every machine goes in another Brewfile.
- Place a new package by role, and never install the same tool through two managers. apt (`scripts/bootstrap/linux/apt-packages.txt`) takes what needs root or runs before brew: compilers via `build-essential`, `curl`, zsh until Homebrew's is installed, and network utilities that want raw sockets. `homebrew/Brewfile.core` is the default for userland CLI tools on both platforms (fresher than Debian stable, and covers tools apt lacks); other Brewfiles hold persona-specific, GUI, or macOS-only apps and casks. Vault tooling (Obsidian, restic) is in `Brewfile.home` only: a server gets none of it from this repo, and the vault's own scripts install what its backups need. System daemons (Docker, Tailscale, Pi-hole, and Unbound from apt beside Pi-hole) come from the vendor's official installer through a script in `scripts/bootstrap/linux/`, applied as an optional install or a role ([`roles/`](../roles/README.md)); on a Mac, Docker and Tailscale are the macOS picker's, and the install scripts skip a tool Homebrew already put in place. A Mac app with no cask (Holeberry) comes from its release through an optional install's script in `scripts/bootstrap/macos/`. Bootstrap runs apt first, then brew; `tests/brew.bats` fails when the git config references a tool no Brewfile installs.

## Where a tool comes from

One source per kind of tool. Agents follow this on every machine (the agents repo's install rule points here), and the shell refuses the two installs it rules out.

- **zsh:** Homebrew's on both platforms (`Brewfile.core`); `install.sh` makes the `zsh` first on PATH, Homebrew's, the login shell. On Linux, apt's zsh stays as the shell that exists before Homebrew does.
- **What the OS ships:** on a Mac, git, curl, and bash are Apple's, never Homebrew's. `tests/run_tests.sh` builds its own bash for Bats into the test cache (`tests/README.md`).
- **A command-line tool you always want:** `Brewfile.core` (`df-add brew NAME`), or apt for what needs root or runs before brew (above).
- **A Mac app:** a cask in a Brewfile; adopt one installed by hand with `brew install --cask --adopt NAME`. App Store apps are `mas` entries.
- **A one-off run:** `uvx`, `npx`, or `bunx`; nothing stays installed.
- **A Python tool you keep:** `uv tool install`. Never `pipx`, and never `pip` outside a virtualenv: `.zshenv` sets `PIP_REQUIRE_VIRTUALENV=1`.
- **Python itself:** uv's, never Homebrew's or Apple's. A Python script in this repo starts with `#!/usr/bin/env -S uv run --script` and a `requires-python` line (`stow/tools/.local/bin/ai-doctor`), so uv supplies an interpreter new enough wherever `python3` on `PATH` is not; the test suite's `python3` is uv's too.
- **Never `npm install -g`:** the `npm` shell function refuses global installs (`NPM_ALLOW_GLOBAL=1 npm …` for a one-time exception). Homebrew's own npm updates with `brew upgrade node`.
- **MCP servers:** ideally as `uvx`, `npx`, or `bunx` commands, so nothing has to be installed first; give a GUI app an absolute path, since it doesn't read the shell's PATH.
