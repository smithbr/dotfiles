# stow/

Everything linked into `~`. Linking itself is described in [`scripts/README.md`](../scripts/README.md); repo-wide rules are in the [root `AGENTS.md`](../AGENTS.md).

## Layers

- `stow/<layer>/` mirrors the home directory under real file names, and `stow/<layer>.<os>/` holds that layer's platform-only files; a machine links the layers its persona and its chosen roles list ([`roles/`](../roles/README.md); the optional installs bring none). Layers: `common` (shell, git, and CLI config every persona gets), `tools` (personal CLI tools such as `sshkey`, `os-doctor`, `df-doctor`, `ai-doctor`), `personal` (what `home`, `server`, and `vps` use but a work Mac does not: `cf-cert`, `df-deploy`, `firetv` (debloats the TCL Fire TV over ADB), `ph` (administers the Pi-hole over its API from any machine on the tailnet), `ts-test`, the personal git identity in `config.personal`, and the gh login seed), `desktop` (GUI app config: the Ghostty variants in `desktop`, and the macOS-only rest in `desktop.darwin`), `server` (`server.linux` holds the server git config), and `pihole` (`pihole.linux` holds the Pi-hole tools; linked by the `pihole` role, not a persona). Put a new file in the narrowest layer that fits; a script that calls a tool from another layer must also find it when run from the repo. Linking uses `--no-folding`, so directories in `~` stay real and only files are symlinks. Switching persona removes the old layers' links as stale. Repository tooling belongs outside `stow/`. Edits to an existing linked file take effect immediately, so edit the repo file, never replace the link in `~`; after adding, removing, or renaming a file under `stow/`, run `scripts/link.sh`.
- Git identity: `stow/common/.config/git/config` sets no `[user]`; it includes the layer files (`config.desktop`, `config.server`, `config.personal`) and then `config.local`, which wins. Only the `personal` layer brings an identity, so a `work` machine sets name, email, and any signing key in `~/.config/git/config.local`. Git reads `~/.gitconfig` after `~/.config/git/config`, so a `[user]` left there silently beats `config.local`. A real `link.sh` run warns about that, and about a missing `user.email`, and `status` and the file review report them; neither prompts nor edits git config.

## iTerm2 and `st` (`desktop.darwin`)

- iTerm2's profile is the Dynamic Profile `stow/desktop.darwin/Library/Application Support/iTerm2/DynamicProfiles/dotfiles.json`, named `dotfiles` (JetBrains Mono Nerd Font 16, full screen, `xterm-256color`, no close prompt; Catppuccin Mocha in dark mode, Latte in light mode). It holds only settings that differ from iTerm2's defaults, and its colors are copied exactly from the presets in `stow/desktop.darwin/.config/iterm2/` (`Catppuccin {Frappe,Latte,Macchiato,Mocha}.itermcolors`). It is not `Rewritable`: iTerm2's write-back saved only part of the profile, so GUI edits don't persist. Change this file instead. Settings outside profiles are applied by `scripts/bootstrap/macos/iterm2.sh` ([`scripts/bootstrap/README.md`](../scripts/bootstrap/README.md)); keep the `Guid` in both files the same.
- `st` (in `desktop.darwin`) opens Claude Code in a new iTerm2 window: `st TEAM` for a team in `~/.config/claude-team/teams.toml`, `st AGENT` (or `st TEAM/AGENT` when the name is in two teams) for one agent with its team's settings, `st DIR`, or bare `st` for the current directory. That teams file is local and untracked; the repo tracks only `teams.toml.example` beside it, which documents every key and which `st` never reads, and `st` says to copy it when the teams file is missing. Keep team and agent names short, since they are what you type (`st df`).

## Tools

- `df-link`, `df-doctor`, `df-add`, `df-rm`, and `df-mv` (`tools`) are wrappers for scripts in `scripts/`, documented in [`scripts/README.md`](../scripts/README.md).
- `df-deploy HOST...` (or the hosts in `DF_DEPLOY_HOSTS`) brings other machines up to date after a push: over `ssh -t`, each host pulls `~/.dotfiles` fast-forward only and runs `scripts/link.sh`. It warns when this checkout has unpushed commits, and one failing host does not stop the rest.
- `ai-doctor` (Python 3, standard library only) prints a one-line summary of Claude Code, Codex, and Cursor (skills and their token cost, plugins, MCP servers), then a numbered list of only what to do, fixes first, each with its one command or step: an MCP server that can't start, a token written into MCP config (never printed), a broken skill link, skill bundles beyond the persona's `skills=`, a plugin both installed and synced from claude.ai, and plugin servers waiting for a sign-in. `ai-doctor --fix` does the items marked `[auto]`, asking before each (`--yes` asks nothing; closed stdin without `--yes` changes nothing): `skills-add` for bundles, the app's own `claude mcp remove` or `codex mcp remove` when installed and otherwise an edit of its config, the URL moved from `command` to `url`, `chmod 600`, and removing a broken link or a duplicate plugin. Each file is backed up to `~/.local/state/ai-doctor/<time>/` before its first change. Rotating a token and turning off claude.ai plugins stay by hand. `-v` adds everything checked (instruction files, skills per bundle, plugins, servers, experimental flags) and `--app` limits it to one app. It exits 1 while a fix is left. Reading Codex's `config.toml` needs Python 3.11; the macOS system `python3` (3.9) skips it.
