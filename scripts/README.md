# scripts/

Repository tooling: the linker, the Brewfile helper, the file review, and `common.sh`. Bootstrap has its own rules in [`bootstrap/README.md`](bootstrap/README.md); repo-wide rules are in the [root `AGENTS.md`](../AGENTS.md).

## Linking

`scripts/link.sh` is the linking step on its own: `link.sh` links, `link.sh add PATH... [--layer NAME] [--platform] [--seed]` starts managing files already in `~` (it copies them into the layer, or its `<layer>.<os>` part, then links them; `--seed` copies to `seed/` instead; without `--layer` it asks on a terminal, describing each layer by what belongs in it (`common`, `tools`, `personal`, `desktop`, `server`, `pihole`; `layer_rule` in `link.sh`) or else by its top-level paths, then the personas that link it and `macOS only` or `Linux only` for a platform part; it fails on closed stdin; it refuses paths outside the destination, symlinks, files already in the repo, `.local` overrides, editor settings, private agent paths, private keys and other secrets, and files with a banned word, before copying anything), `link.sh rm PATH... [--delete]` is its inverse (each path must be a link into the repo's `stow/`, or a directory, meaning every such link in it; it replaces each link with a real copy of the repo file, keeping its mode, then `git rm`s the repo file and removes the folders that leaves empty in the layer; `--delete` instead moves the file out of `~` into `~/.local/state/dotfiles/cleanup/<timestamp>.remove/`; it refuses paths outside the destination, real files, seed files, foreign, agent, and editor links before changing anything, and leaves the commit to you; other machines drop the link as stale on their next `df-link` or `df-deploy`, losing the file there unless `df-rm` runs on them before the pull), `link.sh mv PATH... [--layer NAME] [--platform | --no-platform]` moves the same kind of paths to another layer, or renames a file you already moved or renamed in `~` (`mv ~/.config/app/old ~/.config/app/new`, then `df-mv ~/.config/app/new`: the link is found even when the move broke it, its repo file gets the new path, the layer prompt defaults to the file's current layer (without a terminal or `--layer` it stays there), and a new name `add` would refuse is refused) (it copies each repo file to the same path in the target package, swaps the link in `~` to it with a rename so the file never goes missing, then `git mv`s the repo file over the copy, so the index shows a rename, and removes the folders left empty; the file stays in or out of a `<layer>.<os>` part unless `--platform` puts it in this OS's part or `--no-platform` takes it out; without `--layer` it asks with `add`'s layer prompt and fails on closed stdin; it refuses whatever `rm` refuses, a layer this persona does not link (naming the personas that do), the file's current place, and a destination the layer already has, before changing anything; afterwards it lists, without editing, the repo lines that still name the old path (`git grep`), and leaves the commit to you; other machines follow the new layer on their next `df-link` or `df-deploy`, and one whose persona does not link it loses the file), `link.sh persona` prints the persona in effect and its source, `link.sh personas` lists the ones this OS allows, `link.sh offered` lists the installs offered here (the optional installs, then the persona's roles) with each one's detect command, `link.sh installs` prints the Brewfiles (the persona's and the chosen roles'), the persona's `harden` setting, the chosen installs in run order with their source, and an `install=` line per install (the chosen installs come from `DOTFILES_INSTALLS`, else the saved choice, else what is on by default, and bring the roles' layers; see [`roles/README.md`](../roles/README.md)), `link.sh status` lists missing, replaced, foreign, broken, and stale links, plus `shadowed` when `~/.gitconfig` sets `[user]`, `unset` when git has no `user.email`, and `unlinked` for a real, non-empty file or folder where a layer the persona does not link would put its files (the shallowest path no other layer uses, such as `~/.local/bin/cf-cert` on `work`; never moved), `link.sh managed` prints every path the repo owns, and `--persona NAME`, `--dry-run`, `--refresh` (pull `~/.config/agents` now; otherwise `link.sh` pulls at most weekly, while `install.sh` always passes it), and `--destination PATH` adjust a run. A run prints the persona and its layers, each link it makes and each file or old link it clears, one line per step saying how many of its links are in place and how many are new (the layers, editor settings, agent and skill links, the agents checkout, and seed files), and a closing count; a dry run lists the links it would make instead of stow's own preview. Stow's `--target` and `--dir` are rejected; use `--destination`. The `tools` layer puts thin wrappers on the PATH: `df-link` runs `scripts/link.sh` with its arguments, `df-doctor` runs `scripts/doctor.sh` with its arguments (the report, then on a terminal the list of changes), `df-rm PATH...` is `link.sh rm`, `df-mv PATH...` is `link.sh mv`, and `df-add` starts managing something: `df-add stow PATH...` is `link.sh add`, and `df-add brew NAME...` runs `scripts/brew-add.sh`, which installs each package (`--no-install` skips that) and adds it to a Brewfile in `homebrew/`, sorted among entries of its kind in the chosen section, with formulae before casks. It detects a cask when no formula has the name (`--cask`/`--formula` override), skips names any Brewfile already lists (tap-qualified names match by short name), and records nothing when the install fails. Without `--file` (core, home, work, macos) it offers the persona's Brewfiles on a terminal, and without `--section` it asks when the file has more than one section; closed stdin fails with the choices instead. Each finds the repo through its own stow link, so the scripts stay in `scripts/`, where bootstrap needs them before anything is linked.

- Links into the private agents checkout (`~/.config/agents`) and the directories kept at mode 700 are listed in `AGENT_LINKS` and `PRIVATE_DIRS` in `scripts/link.sh`. Git keeps only the executable bit, so any other permission must be applied there.
- A link into the repo's `stow/` or `editors/` that no longer belongs on this host (its file moved or was deleted, or its package no longer applies) is stale: `link.sh` removes it and `status` reports it. Candidates come from every package, the repo's `stow/` history, and each platform's editor directories. Only links are removed, never real files, so moving or deleting a managed file needs no manual cleanup.
- An application that saves by replacing its config file turns the link into a real file and silently detaches it from the repo. `link.sh status` and the file review report these as `replaced`.

## df-doctor: the machine check and cleanup

- `scripts/doctor.sh` (run as `df-doctor`) checks the machine against the repo in one pass and sorts every finding into a group: **Links** (repo links `link.sh status` reports as off, plus broken managed links; repair them, then run `df-link`), **Fix** (changes df-doctor suggests: archive junk, backup copies, broken links in `~/.local/bin`, old zsh completion caches, and the old copy of a tool a new shell now sends elsewhere; move a file where xdg-ninja's advice says), **Decide** (needs a person: no owner found, marked `likely leftover` when it is also untouched past `--days`; XDG advice to follow by hand on a `how:` line; an unmanaged file next to managed files), **Not in the repo** (each entry directly in the XDG config folder and each command in the XDG bin folder that the repo does not manage, so config and tools made outside the repo show up, with the owner and last change or what a link points to; a stale unowned config folder goes under Decide instead), and **Ignore** (in use, local state, tools without XDG support, and paths marked to ignore; counted, and listed with `--all` under a heading per kind). The report opens with the home and a count per group, or `✓ Nothing to fix` when only ignored items remain; a Links row names its `link.sh status` state, a Fix row starts with its change (`archive:`, `move:`), and a path too long for its column gets a line of its own. Saved backups get one summary line. Without a terminal, or with `--report`, it only reports.
- What it checks: each unmanaged dotfile directly in the home; everything directly in the XDG config and bin folders (a new shell's `XDG_CONFIG_HOME` and `XDG_BIN_HOME`, else `~/.config` and `~/.local/bin`), a folder there that holds managed files being looked into rather than listed; and the unmanaged files in other folders that hold managed files. Folders named on the command line are checked in full. Credentials, private agent directories, the repo, managed paths, and expected local overrides (an unmanaged file whose `.example` the repo manages, such as `config.local` or `teams.toml`) are never findings. Unmanaged does not mean unused.
- XDG knowledge comes from xdg-ninja's program data (found under Homebrew's usual prefixes; `DF_DOCTOR_PROGRAMS` and `DF_DOCTOR_PREFIXES` override that) and from the environment a new zsh starts with, read once from the home's own `.zshenv`, so a value exported only in the running shell does not count. Without xdg-ninja or jq the report says so and gives no XDG advice. An owner is a command named like the entry, or an app with that name (or starting with it, for names of four letters or more); folders named unlike their command, such as `.vscode*` or `bottom`, are mapped in `owner_alias`, so each note also says when the entry last changed.
- On a terminal (stdin and stdout), `df-doctor` follows the report with one list of every Fix, Decide, and Not-in-the-repo item df-doctor may change, one row each, set to its suggestion: a Fix item's archive or move, skip for the rest, plus one `relink` row (runs `df-link`) when repo links are missing or stale. On the alternate screen, rows run Fix, Decide, then Not in the repo; the arrows, PgUp, PgDn, Home, and End choose a row and its first letter sets the change: `s` skip (leave it alone this time; the next run reports it again), `a` archive, `d` delete, `i` ignore, `r` add to the repo, `m` move (only where xdg-ninja names a target); space cycles. The foot shows what Enter would change (`archive 2 · delete 1`) and the highlighted row's group, full reason, and `how:` advice or move target. Enter applies every row at once, and `q` or Esc changes nothing. Delete lists what it will remove and asks once more (`gum confirm`, else `[y/N]`), defaulting to no; anything but a yes keeps those items and applies the rest. A closing line sums up what was done, or says it was done with problems. While the check runs, a terminal shows `Checking ~…`, and the report's group headings are colored unless the output is piped or `NO_COLOR` is set. `--fix` shows the list without a terminal too, and then reads one line instead (`DOTFILES_PROMPT=read` forces this): action words, each followed by row numbers or ranges (`delete 2 5-7 ignore 3`), with `none` setting every row to skip (`keep` is accepted for skip) and Enter applying the list as shown; a word or row it cannot use changes nothing. Closed stdin, non-interactive installs, dry runs, and an incomplete check never change anything; an incomplete check (for example when the managed paths cannot be listed) is reported and makes the run fail.
- Archive moves the file into `~/.local/state/dotfiles/cleanup/<timestamp>.<suffix>/` with private permissions and original relative paths. It never follows symlinked parents; restore a file by moving it back after checking for conflicts. Delete is `rm -rf` on the path, which removes a symlink rather than its target, and keeps no copy. Manage runs `link.sh add` on that one path, with its refusals and its layer question (without a terminal it fails, since there is no `--layer` to pass); a refused path stays, the run says so and exits non-zero, and the other changes still apply. Deletes run first, then archives, moves, and adds, after checking that nothing became managed during the run; paths to ignore are recorded last, and `relink` runs after everything else.
- Ignore marks a path as fine for this machine: it and everything in it report under Ignore as `marked to ignore`, whatever group they would be in, except repo links that are off. `df-doctor --ignore PATH` marks one directly and `df-doctor --unignore PATH` reports it again (a path only covered by an ignored folder stays ignored, and the message names the folder); `--explain` names the entry that covers a path. The list is `~/.local/state/dotfiles/doctor-ignore`, one `~/`-relative path per line (`#` comments allowed, editable by hand), private, and per machine rather than in the repo, since what is local state differs from machine to machine; anything every machine should ignore belongs in `is_local_state` in `doctor.sh`. It refuses paths outside the home and a symlinked state folder.
- Move follows xdg-ninja's advice: it is offered when the advice says to move the file or directory (not just "it") to one `$XDG_*_HOME` path and the entry is that kind, as with `~/.tmux.conf` to `~/.config/tmux/tmux.conf`, under the base a new zsh gives the XDG variable. Advice that also exports variables (less before 598) waits until a new shell sets them all. A target that already exists goes under Decide for a hand merge. Version notes in the advice are not checked, since only the latest two OS releases are supported. The move is a rename: it refuses a symlink, an existing target, a symlinked parent, a target on another filesystem, or a path a running program has open (`lsof`, when installed; quit the program first, for example `colima stop`), and logs `time<TAB>from<TAB>to` to `~/.local/state/dotfiles/moves.tsv`, printing the `mv` that undoes it.
- `--explain PATH` prints one finding with its size, last change, and xdg-ninja's full advice; `--days N` sets when an unowned entry counts as untouched (default 90). For the installer and tests: `--source PATH` and `--destination PATH` pick another repo or home, `--no-hint` drops the closing hint, `--fix-only` shows the list without the report, `--report` never shows it, and `--tsv` prints the findings as group, path, action, target, and reason.
- Installation ends with the report in a box (`--report`, plus `--no-hint` when the list follows), then interactive installs run `doctor.sh --fix-only` unboxed so the list can use the terminal. A failed check skips the list.
