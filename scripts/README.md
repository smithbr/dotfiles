# scripts/

Repository tooling: the linker, the Brewfile helper, the file review, and `common.sh`. Bootstrap has its own rules in [`bootstrap/README.md`](bootstrap/README.md); repo-wide rules are in the [root `AGENTS.md`](../AGENTS.md).

## Linking

`scripts/link.sh` is the linking step on its own: `link.sh` links, `link.sh add PATH... [--layer NAME] [--platform] [--seed]` starts managing files already in `~` (it copies them into the layer, or its `<layer>.<os>` part, then links them; `--seed` copies to `seed/` instead; without `--layer` it asks on a terminal, describing each layer from the tree (its top-level paths, the personas that link it, and `macOS only` or `Linux only` for a platform part), and fails on closed stdin; it refuses paths outside the destination, symlinks, files already in the repo, `.local` overrides, editor settings, private agent paths, private keys and other secrets, and files with a banned word, before copying anything), `link.sh remove PATH... [--delete]` is its inverse (each path must be a link into the repo's `stow/`, or a directory, meaning every such link in it; it replaces each link with a real copy of the repo file, keeping its mode, then `git rm`s the repo file and removes the folders that leaves empty in the layer; `--delete` instead moves the file out of `~` into `~/.local/state/dotfiles/cleanup/<timestamp>.remove/`; it refuses paths outside the destination, real files, seed files, foreign, agent, and editor links before changing anything, and leaves the commit to you; other machines drop the link as stale on their next `df-link` or `df-deploy`, losing the file there unless `df-remove` runs on them before the pull), `link.sh persona` prints the persona in effect and its source, `link.sh personas` lists the ones this OS allows, `link.sh offered` lists the installs offered here (the optional installs, then the persona's roles) with each one's detect command, `link.sh installs` prints the Brewfiles (the persona's and the chosen roles'), the persona's `harden` setting, the chosen installs in run order with their source, and an `install=` line per install (the chosen installs come from `DOTFILES_INSTALLS`, else the saved choice, else what is on by default, and bring the roles' layers; see [`roles/README.md`](../roles/README.md)), `link.sh status` lists missing, replaced, foreign, broken, and stale links, plus `shadowed` when `~/.gitconfig` sets `[user]`, `unset` when git has no `user.email`, and `unlinked` for a real, non-empty file or folder where a layer the persona does not link would put its files (the shallowest path no other layer uses, such as `~/.local/bin/cf-cert` on `work`; never moved), `link.sh managed` prints every path the repo owns, and `--persona NAME`, `--dry-run`, `--refresh` (pull `~/.config/agents` now; otherwise `link.sh` pulls at most weekly, while `install.sh` always passes it), and `--destination PATH` adjust a run. Stow's `--target` and `--dir` are rejected; use `--destination`. The `tools` layer puts thin wrappers on the PATH: `df-link` runs `scripts/link.sh` with its arguments, `df-file-review` runs `scripts/file-review.sh` (`--cleanup` when given no arguments), `df-remove PATH...` is `link.sh remove`, and `df-add` starts managing something: `df-add stow PATH...` is `link.sh add`, and `df-add brew NAME...` runs `scripts/brew-add.sh`, which installs each package (`--no-install` skips that) and adds it to a Brewfile in `homebrew/`, sorted among entries of its kind in the chosen section, with formulae before casks. It detects a cask when no formula has the name (`--cask`/`--formula` override), skips names any Brewfile already lists (tap-qualified names match by short name), and records nothing when the install fails. Without `--file` (core, home, work, macos) it offers the persona's Brewfiles on a terminal, and without `--section` it asks when the file has more than one section; closed stdin fails with the choices instead. Each finds the repo through its own stow link, so the scripts stay in `scripts/`, where bootstrap needs them before anything is linked.

- Links into the private agents checkout (`~/.config/agents`) and the directories kept at mode 700 are listed in `AGENT_LINKS` and `PRIVATE_DIRS` in `scripts/link.sh`. Git keeps only the executable bit, so any other permission must be applied there.
- A link into the repo's `stow/` or `editors/` that no longer belongs on this host (its file moved or was deleted, or its package no longer applies) is stale: `link.sh` removes it and `status` reports it. Candidates come from every package, the repo's `stow/` history, and each platform's editor directories. Only links are removed, never real files, so moving or deleting a managed file needs no manual cleanup.
- An application that saves by replacing its config file turns the link into a real file and silently detaches it from the repo. `link.sh status` and the file review report these as `replaced`.

## File review and cleanup

- Installation ends with a file review. It lists unmanaged dotfiles directly under the destination home, unmanaged neighbors of managed files, broken managed links, and saved migration backups. The home dotfiles are grouped by `home-audit`'s verdict (junk, leftover, could move, review, in use), each with its size and reason, most likely abandoned first; the archive picker offers candidates in that order with the same reason. `file-review.sh` runs the repo's copy of `home-audit --tsv`, so it works whatever layers the persona links; if it fails, entries are listed without verdicts. Unmanaged does not mean unused; credentials, private agent directories, managed paths, and expected local overrides (an unmanaged file whose `.example` the repo manages, such as `config.local` or `teams.toml`) are excluded from cleanup.
- The install step prints the review in a box, then interactive installs run `file-review.sh --select` unboxed so the archive picker can use the terminal. With gum on a terminal it is a multi-select (tab or x toggles, since gum 2 ignores space; ctrl+a for all, Esc skips) followed by a confirmation that defaults to no; otherwise it is one numbered selection (or `all`) where Enter skips. Closed stdin, non-interactive installs, and dry runs only report; they never archive. Failed inventory queries disable cleanup and report an incomplete review.
- Run `df-file-review` (or `./scripts/file-review.sh --cleanup`) to repeat the review and selection without reinstalling. Use `--source PATH` for another source tree and `--destination PATH` for another destination. `--select` shows only the picker, and `--no-cleanup-hint` drops the closing hint. Extra positional roots expand the recursive scan; `--all` shows normally hidden runtime state but does not select it for cleanup.
- Cleanup moves selected paths into `~/.local/state/dotfiles/cleanup/<timestamp>.<suffix>/` with private permissions and original relative paths. It never permanently deletes them or follows symlinked parents. Restore needed files to their original paths after checking for conflicts. Existing migration backups are reported separately and are not cleanup candidates.
- `home-audit`, which supplies the verdicts, is documented in [`stow/README.md`](../stow/README.md).
