# roles/

What a machine is for, beside the persona that says whose it is. A role (`roles/<name>`, plain `key=value` lines parsed like a persona, never sourced) names `os` (allowed platforms), `layers` (linked like the persona's own), `brew` (Brewfiles installed in full), `requires` (installs applied first, chosen or not; a role or an optional install), `detect` (a command that succeeds once the role is applied, run with `bash -c` with `scripts/common.sh` sourced), and `setup` (the script `install.sh` runs when detect fails: `scripts/bootstrap/<os>/<setup>.sh` or `scripts/bootstrap/<setup>.sh`, the role's own name when left out). A persona lists roles in `roles` (on by default) and `roles_optional` (offered).

- Beside the roles stand the optional installs, which no persona lists: a setup script in `scripts/bootstrap/<os>/` or `scripts/bootstrap/` with a `# detect: COMMAND` line is offered to every persona on its OS, on by default. Today `linux/docker.sh`, `linux/tailscale.sh`, `macos/holeberry.sh` (the Holeberry menu bar app, which has no cask; it detects its app bundle in `/Applications`), and `claude-code.sh` (both OSes); the command-line tools detect with `tool_installed NAME` from `scripts/common.sh`, which looks on PATH, in `~/.local/bin`, and in Homebrew's bin (`HOMEBREW_PREFIX`, else its usual prefixes), so a tool installed through Homebrew is not installed natively as well, and the other way round. A role's setup script declares no detect line: the role file does.
- `install.sh` asks which installs a machine gets once, on a terminal, with the saved choice and the installs already applied preselected, and remembers the answer in `~/.local/state/dotfiles/installs`; `--install NAME`, `--no-install NAME`, and `DOTFILES_INSTALLS` answer without a terminal, `--reconfigure` asks again, and closed stdin keeps the saved choice (a fresh machine gets the optional installs and the persona's default roles). Installs run last, in `requires` order, each skipped when its detect command succeeds and recorded either way, so the next run retries a failed one. A setup script's output streams as it happens, indented under the step (a vendor installer may take minutes or print a login URL); `install.sh --verbose` shows it raw. An install must be safe to run again.
- `pihole` brings the `pihole` layer (the `ph-*` tools) and sets up Pi-hole with Unbound as its upstream (`scripts/bootstrap/linux/pihole.sh`: Unbound from apt on `127.0.0.1#5335` with the guide's config, Pi-hole unattended through its official installer, pointed at Unbound with its own DNSSEC off; `PIHOLE_UPSTREAMS` overrides the upstreams); its web password is a next step. The role counts as applied once both are installed and Unbound has its Pi-hole config, and a rerun brings Pi-hole's upstreams and DNSSEC setting back in line. It requires `tailscale`, which joins even when unticked.
- A new role is a file here plus a setup script in `scripts/bootstrap/`; add it to the personas that should offer it. A new optional install is only the setup script, with its detect line. `scripts/link.sh offered` lists what a persona is offered on this OS and `scripts/link.sh installs` the chosen installs in run order.
